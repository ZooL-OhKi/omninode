# Native host setup

install_windows.py is dry-run by default. --extension-id must be the actual unpacked extension ID (32 lowercase letters a-p). --browser selects chrome or edge. --apply is the only installation path and supports Windows only. It creates a dedicated venv under LOCALAPPDATA/OmniNode/NativeHost-<browser>/runtime, installs desktop/requirements-windows.txt there, writes a host launcher and native manifest, and registers only the current user's selected browser under HKCU. No elevation, global pip install, service, firewall change or automatic desktop activation is performed. Native consent remains required per session.

Registration permits exactly one chrome-extension origin; wildcards are not accepted. Existing setup directories without matching source/origin/browser ownership metadata and registrations pointing elsewhere are refused. Linked/junction paths and CMD metacharacters are rejected where checked. Source and setup paths currently require printable ASCII. This is not a certification against all filesystem races or malicious local users. Dependencies are direct-version-pinned but transitives are not fully locked. A failed apply may leave a partial managed runtime; no destructive cleanup or full transactional rollback is implemented.
